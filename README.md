# Автоматизация управленческого отчёта P&L из ОСВ (1С)

Программа на Python, которая за один запуск превращает выгрузку оборотно-сальдовых ведомостей (ОСВ) из 1С в управленческий отчёт о прибылях и убытках (P&L) в Excel.

Раньше отчёт собирался вручную: на каждую строку P&L вручную подставлялись ссылки на ячейки ОСВ. Сборка отчёта занимала 2 рабочих дня. Теперь соответствие «статья из 1С → строка отчёта» хранится в справочнике, а расчёт, итоги и проверки выполняет программа. Время сборки сократилось до 30 минут, включая скачивание ОСВ из 1С и сверку итогов.

> Проект учебный и сделан на реальной задаче. Реальные данные компании в репозиторий не входят. Для пробного запуска есть выдуманная ОСВ в папке `examples/`.

## Что получается на выходе

Excel-файл `data_output/PL_<год>-<месяц>.xlsx` в тысячах тенге:

- все строки шаблона в фиксированном порядке (пустые статьи остаются с нулями);
- итоги по разделам: доход, себестоимость, расходы по реализации, административные расходы;
- валовая прибыль, EBITDA, операционная прибыль, EBIT, EBT, чистая прибыль;
- оформление: жирные итоги, формат чисел, серая заливка прибылей.

**Пример готового результата:** файл [`examples/PL_2025-01.xlsx`](examples/PL_2025-01.xlsx). Он построен программой по выдуманной ОСВ из той же папки (`examples/OSV_example.xlsx`), так что результат можно посмотреть, не запуская код.

## Как это работает

1. Берёт единственный файл ОСВ из папки `data_input`.
2. Находит в листе «ОСВ» блоки по счетам (6010, 6100, 6200, 7010, 7110, 7210, 7300, 7400, 7710) и вытаскивает из каждого строки-статьи. Вложенность строк определяется по отступам ячеек.
3. Определяет период по заголовку («за Октябрь 2024 г.» → `2024-10`).
4. Присоединяет справочник `mapping.xlsx`: пара «счёт + статья в ОСВ» → строка P&L. Статьи, которых в справочнике нет, не теряются, а уходят в запасную строку своего счёта и выводятся списком «Нераспознанные статьи».
5. Применяет вводимые вручную доли из `settings.xlsx` (газ и логистика, например 60/40).
6. Складывает суммы по строкам P&L и считает итоги по формулам отчёта.
7. Сохраняет Excel в порядке, заданном `layout.xlsx`.
8. Проверяет, что сумма по каждому счёту в отчёте равна сумме в ОСВ.

## Быстрый старт на примере

Нужен Python 3.11 или новее (проверено на 3.13).

```powershell
pip install -r requirements.txt
mkdir data_input
copy examples\OSV_example.xlsx data_input\
python Reporting_Automation.py
```

Программа покажет значения из `settings.xlsx` и остановится. Нажмите Enter, чтобы продолжить. Результат появится в `data_output/PL_2025-01.xlsx`, а внизу терминала будет сообщение «Контроль пройден». Готовый файл для сравнения лежит в `examples/PL_2025-01.xlsx`.

Пример `examples/OSV_example.xlsx` полностью выдуман: названия статей общие, суммы случайные, но структура такая же, как у реальной выгрузки (отступы, строки «Головное подразделение», строки `<...>`, итоги).

## Какие файлы нужны программе

| Файл | Назначение |
|---|---|
| `data_input/*.xlsx` | ОСВ из 1С. Ровно один файл на запуск (один месяц). В git не попадает |
| `mapping.xlsx` | Справочник: счёт + статья в ОСВ → раздел и строка P&L, знак (+1 или −1) |
| `layout.xlsx` | Порядок строк итогового отчёта |
| `settings.xlsx` | Вводимые вручную значения: доли газа и логистики |

### Требования к выгрузке из 1С

- Лист называется «ОСВ». Название статьи в столбце A, обороты по дебету в E, по кредиту в F.
- Заголовок каждого блока в виде «Оборотно-сальдовая ведомость по счету XXXX за Месяц Год г.».
- Выгружайте все счета отчёта: 6010, 6100, 6200, 7010, 7110, 7210, 7300, 7400.
- **Выгружайте также счёт 7710 (КПН).** Налог программа не рассчитывает, а берёт из ОСВ, начисленный бухгалтером. Если счёта нет в выгрузке, КПН в отчёте будет равен нулю.

## Вводимые вручную значения

Перед расчётом программа показывает доли из `settings.xlsx` и ждёт подтверждения:

```
Значения из ...\settings.xlsx:
  Доля СУГ на ТМЗ - основное производство: 60%
  Доля СУГ на ТМЗ - логистические расходы: 40%

Если изменений нет, нажмите Enter, чтобы продолжить.
Если нужно изменить, поправьте файл, сохраните его (Ctrl+S) и нажмите Enter.
```

После Enter файл читается заново и проверяется: доли должны быть от 0 до 1 и в сумме давать 100%. Иначе программа останавливается с понятным сообщением. Так устаревшие значения не попадут в отчёт незамеченными.

## Принятые решения

- **Доходы берутся по кредиту, расходы по дебету.** Строка `<...>` («аналитика не заполнена») не мусор: в ней бывают реальные суммы, а на противоположной стороне лежит проводка закрытия периода.
- **Ключ справочника: счёт + статья.** Одинаковые названия («Заработная плата», «Материальные затраты») встречаются в разных счетах и относятся к разным строкам отчёта.
- **Запасные правила.** Нераспознанная статья попадает в «Прочее» своего раздела и в отдельный список, а не теряется.
- **Правило по счёту целиком.** Для счёта 7710 название статьи не важно: всё идёт в строку «КПН» и не считается нераспознанным.
- **Разности счетов** (курсовые разницы, финансовые расходы) задаются знаком в справочнике: строки со знаком −1 вычитаются.
- **Ручные корректировки в шаблон не включены.** Программа считает только то, что есть в ОСВ.
- **КПН не рассчитывается.** Налогооблагаемая база отличается от управленческой прибыли (непринимаемые расходы, перенос убытков), поэтому используется начисление из учёта.

## Проверки

- **Контроль сумм.** Для каждого счёта сравниваются сумма в ОСВ и сумма, попавшая в отчёт. Если часть потерялась, программа пишет «ВНИМАНИЕ».
- **Один файл.** Если в `data_input` не один файл, программа останавливается и не смешивает месяцы.
- **Автотесты.** Запуск: `python -m pytest -v`. Шесть тестов проверяют определение периода, разнесение по долям без потери суммы, проверку долей, запасное правило, правило для КПН и то, что контроль замечает потерянную сумму.

## Ограничения и идеи развития

- Один запуск обрабатывает один месяц.
- Названия месяцев в заголовке должны быть на русском («Октябрь»).
- Лист ручных корректировок (период, строка, сумма, комментарий), чтобы вносить их прозрачно, а не править готовый файл.
- Прямая выгрузка данных из 1С (например, через OData) вместо Excel.
- Сравнение нескольких месяцев в одной таблице.

## Как создавался проект

Справочник соответствий (`mapping.xlsx`) и схему автоматизации отчёта разработал автор на основе рабочего шаблона отчёта: какие статьи 1С к каким строкам P&L относятся, как считаются разности счетов, итоги, доли газа и КПН, какие проверки нужны. Эти же правила описаны выше в разделе «Принятые решения».

Код писался пошагово в диалоге с ИИ-ассистентом (Claude): ассистент помогал с реализацией и объяснял логику, а постановку задачи, бизнес-правила и проверку каждого шага по контрольным суммам выполнял автор.
